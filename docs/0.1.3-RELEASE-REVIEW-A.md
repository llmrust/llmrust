## A1. 是否发 0.1.3？

**semver 依据**：0.1.3 相对 0.1.2 **零 breaking change**（API-001 三方事实表 + API-002 semver 门禁背书），纯治理/冻结/善后——故是 0.1.3 而非 0.2.0。

**范围精确化**：0.1.3 不含 Provider 行为修复（流式吞错 STR-002A/G 等留给 0.1.4/0.2），**但承载 API-003 范围内的 E-002 日志行为修复与 429 文档对齐**——并非完全零行为面。

**背景**：M0 门禁全齐；M1 冻结进行中（当前 2/4）。M2/M3 未做。
**选项**：
- (a) M1 DONE 即发——接受"API 冻结但 Provider 行为缺陷未修"的状态
- (b) M2/M3 完成后发——更稳，但周期显著拉长
- (c) 不发 0.1.3，攒到 0.2——放弃当前发布线

**架构师倾向**：(a)。0.1.3 的定位是"治理 + 冻结 + 事故善后"；拖着不发，yanked 0.1.2 就一直是 crates.io 上的最新可见版本，对新用户最不利。
**事实前提（须显式确认）**：发布 0.1.3 后它成为最新非 yanked 版本，0.1.2 退出 latest；**0.1.2 保持 yanked，发布 0.1.3 时不 un-yank**。
