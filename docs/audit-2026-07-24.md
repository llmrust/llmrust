### ⚠️ 两个 proxy 测试失败：非代码缺陷，是测试的环境脆弱性（已定位根因）

- 失败用例：`proxy::tests::serve_starts_and_answers_health`、`proxy::tests::serve_with_bearer_requires_auth`
- 现象：期望 200/401，实得 **502**
- 根因（已实验证实）：这两个测试用 `reqwest::Client::new()` 直连 127.0.0.1。reqwest 会读取 Windows 系统代理（本机 `ProxyEnable=1, 127.0.0.1:7894`），请求被发给本地代理后返回 502。验证实验：同一台服务器，默认 client → 502，`Client::builder().no_proxy()` → 200。
- 建议修复：测试中改用 `reqwest::Client::builder().no_proxy().build()`，与库内 `http.rs` 的 `.no_proxy()` 策略保持一致。约 2 行改动。

## 二、契约符合性（对照 docs/CONTRACTS.md）

### 🔴 P1 — Anthropic / Gemini 流式解析静默丢弃畸形数据（违反契约）

CONTRACTS「stream」第 5 条 + CAPABILITIES「Streaming behavior」第 3 条 + capabilities.json `design_principles` 均声明：*"Parse errors in the stream are surfaced as Err(LlmError::Parse) — never silently dropped."*

但：

- `src/providers/anthropic.rs:483` — `let Ok(event) = serde_json::from_str(...) else { return Vec::new(); }`：畸形 SSE 行被静默跳过。
- `src/providers/google.rs:651` — 同样模式，静默跳过。

对照：`compat.rs:321` 与 `ollama.rs:165` 正确返回 `Err(LlmError::Parse(...))`。
建议：统一改为返回 `vec![Err(LlmError::Parse(format!("failed to parse Anthropic/Gemini stream chunk: {e}")))]`，并各加一个畸形行测试。

### 🟡 P2 — Anthropic 流式终块不带 usage

CONTRACTS「stream」第 3 条要求终块携带 `usage`（如上游提供）。Anthropic 在 `message_start` / `message_delta` 事件中上报 usage，但 `AnthropicStreamEvent`（`anthropic.rs:365`）未声明 `usage` 字段，流式路径永远不产出 usage。compat / google / ollama 均已在终块产出 usage。
建议：在事件结构中解析 usage 并挂到 `message_delta` 对应的终块上。

## 四、API 完整性与风格问题（P3）

1. **`ThinkingConfig` 半实现**：`ChatRequest.thinking` / `with_thinking()` 是公开 API，但没有任何 provider 转发它（Anthropic 原生支持 `thinking` 参数却未接入）；反向流式 thinking 增量三家 provider 已实现。公开 API「只能收、不能发」。
2. **导出遗漏**：`lib.rs` 的 `pub use types::{...}` 未导出 `ThinkingConfig`；`prelude.rs` 也未导出 `ThinkingConfig` 和 `FinishReason`（`FinishReason` 在响应结构中随处可见，prelude 用户却要单独 `use llmrust::types::FinishReason`）。
3. **中文 doc 注释混入**：`types.rs` 及三个 provider 中残留 `M2-16：…` 中文里程碑注释（全库其余文档为英文），影响「代码即文档」的一致性；`M2-16` 这类内部里程碑编号对读者无意义。
4. **CHANGELOG 缺口**：thinking / cache token / reasoning token 等 0.1.x 已发布的 additive 字段在 CHANGELOG 无任何条目。
5. **Gemini 非流式路径未区分 thought part**：`google.rs:800-803` 非流式 `chat()` 会把 `thought: true` 的思考 part 一并拼进 `content`；流式路径已正确分流到 `thinking` 字段。两路径行为不一致。
6. **重试放大 `n>1` 警告**：`warn_if_unsupported_n` 注释称「调用一次」，但 `RetryProvider` 每次重试都会重新进入 provider，警告会重复打印（纯噪音，无功能影响）。
7. **Anthropic proxy 的 JSON 解析失败响应不统一**：`/v1/messages` 直接用 `Json<AnthropicRequest>`，畸形 JSON 时返回 axum 默认的纯文本 400，而非 Anthropic 风格错误体（OpenAI 端点已用 `json_rejection_response` 统一处理）。
8. **Anthropic 流式 error 事件后无 `message_stop`**：`anthropic_proxy.rs:738-752` 发出 `error` 事件后直接终止流；Anthropic SDK 通常可容忍，但与 OpenAI 端「error 后仍发 [DONE]」不对称。
